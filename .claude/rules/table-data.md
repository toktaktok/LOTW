# LOTW Table Data

Excel-managed tables: one `TableRowData` class per table. `Map` is excluded (written by the map editor, nested data).

## One table, four files (same name, no `Table` suffix)
| File | Role |
|---|---|
| `Game/Assets/Project/Scripts/Data/Table/Generated/{Name}Data.cs` | C# row fields, generated from the schema by the converter, never edit by hand |
| `Game/Assets/Project/Scripts/Data/Table/{Name}Data.cs` | hand-written `partial` part: class doc, constants, methods. No column fields |
| `Table/Schema/{Name}.json` | column types and rules; source of truth for design docs |
| `Table/Excel/{Name}.xlsx` | data entry |
| `Table/Json/{Name}.json` + `Resources/Table/{Name}.json` | generated by `ConvertTable.bat`, never edit by hand |

## Split tables (`{Schema}_{Part}`)
- `Text_UI.xlsx`, `Text_Item.xlsx` ... share `Schema/Text.json` and the `TextData` class; each file becomes its own JSON (`Text_UI.json`).
- `DataId` only needs to be unique inside one file. `_` in a table name is reserved for this.
- Adding a part = adding an xlsx file. No code change for Text (`Localization` loads every `Resources/Table/Text_*.json`; Text is not registered in `DataManager`).

## Text
Text is referenced only by key (`@key`), never by DataId.

| Part | Contains | Key example |
|---|---|---|
| UI | menus, buttons, settings, HUD, generic verbs, shared talk menu, system messages | `ui.talk`, `ui.talk_menu.end` |
| Dialogue | dialogue lines and NPC-specific choice labels | `dialogue.1100`, `dialogue.common.no_clue` |
| Character | names, titles, profiles | `character.gumman.name` |
| Item | item names, descriptions | `item.rose.desc` |
| World | place names, signs, readable objects, object-specific prompts | `world.plaza.name` |
| Quest | titles, descriptions, objectives | `quest.1.title`, `quest.objective.1001` |
| Notebook | notebook entry titles and bodies | `notebook.101.title`, `notebook.101.body` |

- Pick the part by owner: if deleting an item/NPC/quest would delete the text, it belongs to that part. Text owned by nothing is UI.
- Key: `{part lowercase}.{subject}[.{field}]`, lowercase letters, digits, `_`. The validator enforces the prefix per file and uniqueness across all Text files.
- Every `textKey` column holds a key, never literal text (enforced). Row-owned text: `@{part}.{DataId}[.{field}]`.
- Dialogue row-only line: `@dialogue.{DataId}`. Line reused by several rows: `@dialogue.common.{name}`. Menu choices shared by many NPCs (chat/end): `@ui.talk_menu.*`. Speaker names: `@character.{id}.name`.
- Before adding a text, check whether the same text already exists; reuse the key instead of copying.
- New part only when a new system needs it; until then, put it in the closest part.

## Excel layout
- One sheet, one Excel Table (Insert > Table), top-left at `B2`, style `TableStyleLight9`.
- Row 2: column names in PascalCase (`DataId`, `SpeakerName`). Row 3: type (`int`, `float`, `bool`, `string`, `int[]`), gray text. Data from row 4.
- `string` and `int[]` columns use Text cell format. `int[]` is comma separated (`2,3`).
- Notes go outside the table; the converter ignores them.

## Schema (`Table/Schema/{Name}.json`)
`{ "rowClass": "{Name}Data", "columns": [ { "name", "type", "desc", ...rules } ] }`

| Rule | Meaning |
|---|---|
| `required` | value must be filled |
| `unique` | `true`: no duplicates in the file. `"group"`: none across all files sharing the schema |
| `pattern` | regex the string must fully match |
| `prefixByPart` | value must start with `{part lowercase}.` (`Text_UI` -> `ui.`) |
| `min` / `max` | numeric range |
| `maxCount` | max items in `int[]` |
| `ref` | `"Schema.Column"`; value must exist in that table (or any of its split files). `allow` lists exempt values (`[-1]`) |
| `textKey` | value must be `@key` (literal text is an error), and the key must exist in some `Text_*` file |
| `default` | C# field initializer in the generated class (value when the cell is empty) |
| `commandRefs` | `{"verb": "Schema.Column"}`; in `;`-separated `verb:key...` commands, the key must exist there (Dialogue `item:`, `giveItem:`, `takeItem:` -> `Item.ItemId`) |

Column order and types must match the Excel header and type rows (converter check). The C# fields are generated from the schema on every successful convert (`Generated/{rowClass}.cs`); `TableSchemaTests` checks them too. Change the schema and Excel, then run `ConvertTable.bat`.

## Converter
`ConvertTable.bat [Name]` reads every table (for cross-table refs), validates, and writes nothing if any error. Errors name the cell (`Dialogue.xlsx F12(NextId): ...`). Needs Python 3 + `pip install openpyxl`. `table_edit.py edits.json` (used by the Unity Dialogue Editor) upserts/deletes rows in xlsx tables, validates everything, and saves + converts only if valid. Tests: `python -m unittest test_convert_table test_table_edit` in `Table/`.

## Design docs (`Docs/`)
Each system design doc that uses a table has a `## Table: {Name}` section copied from the schema, not invented:

| Column | Type | Rules | Description |
|---|---|---|---|
| DataId | int | required, unique, min 1 | row ID |
| NextId | int | ref Dialogue.DataId, allow -1 | next row, -1 ends |

Then 2-3 sample rows. Add new columns or rules to the schema first, then update the doc.
