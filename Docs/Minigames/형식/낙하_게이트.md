## 1. 개요

### 1.1 형식 정의
판 위쪽에서 캔이 떨어진다. 캔은 핀에 부딪히면 무작위로 왼쪽이나 오른쪽으로 튄다. 출구 바로 위에는 출구마다 게이트가 1개 있다. 플레이어가 버튼을 누르면 그 출구의 게이트가 잠깐 열린다. 캔이 열린 게이트에 닿으면 그 출구로 바로 떨어진다. 캔이 들어간 출구가 결과가 된다.

- 기본은 운이다. 캔이 어느 게이트에 닿을지는 핀이 정한다. 캔이 닿는 순간에 그 게이트를 열어 두면 그 출구로 받는다.
- 퍼즐의 버튼 게이트와 같은 구조다. 버튼 1개가 게이트 1개를 연다.
- 버튼, 게이트, 출구는 같은 수이고 같은 색으로 짝지어진다.

**잡는 게이트로 바꾼 이유 (0.3)**
- 뒤집는 게이트(왼쪽, 오른쪽 방향 전환)는 버튼을 눌러도 결과가 바로 보이지 않았다.
- 잡는 게이트는 "지금 눌러서 받는다"는 타이밍 재미가 있다. 자판기 버튼을 누르는 행동과도 같다.

### 1.2 사용하는 미니게임

| 미니게임 | 문서 | 이 형식을 쓰는 방식 |
|---|---|---|
| 자판기 룰렛 | [자판기_룰렛.md](../자판기_룰렛.md) | 출구 = 음료 6종. 음료 버튼 6개가 게이트 6개를 연다 |
| 미정 | - | 두 번째 사용처가 필요하다 (미정 1) |

## 2. 화면 명세

### 2.1 스테이지
- 스테이지 크기는 정해져 있지 않다. 미니게임 창의 배치가 `SourceBounds`이면, 발생원 오브젝트가 화면에서 차지하는 크기(월드 RT 픽셀)가 그대로 스테이지 크기가 된다.
- 판은 주어진 스테이지 크기에 맞춰 자동으로 만든다. 핀 줄 수와 간격은 크기에서 계산한다.
- 카메라: 직교 카메라 1대. 스테이지 1픽셀 = 그림 1픽셀 (PPU 25).

### 2.2 화면 구성

```
+--------------------------------+
|            [1] 투입구            |
|    o    o    o    o    o       |  [2] 핀 (엇갈린 줄)
|  o    o    o    o    o    o    |
|    o    o    o    o    o       |
|  =G1= =G2= =G3= =G4= =G5= =G6=  |  [3] 게이트 줄 (출구 바로 위 한 줄)
| o    o    o    o    o    o    o |  마지막 줄 핀 (칸막이 위)
| [ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ] |  [4] 출구 (음료 캔 윗면 견본)
| ( 1 )( 2 )( 3 )( 4 )( 5 )( 6 ) |  [5] 버튼 (출구 아래)
+--------------------------------+
```

| 번호 | 요소 | 설명 | 상태 변화 |
|---|---|---|---|
| 1 | 투입구 | 캔이 나오는 곳 | 준비 상태에서 캔이 흔들림 |
| 2 | 핀 | 캔이 닿으면 무작위로 좌우로 보낸다 | 닿을 때 밝아지고 1픽셀 밀림, 불똥 |
| 3 | 게이트 | 출구 i 바로 위에 있는 문짝 2개. 색 = 출구 i의 음료 색 | 버튼을 누르면 문짝이 아래로 열렸다가 `gateOpenTime` 뒤에 닫힘. 닫힌 채 캔에 맞으면 출렁임 |
| 4 | 출구 | 칸마다 음료의 캔 윗면 견본. 음료는 색으로만 구분한다 | 캔이 들어가면 빛남 |
| 5 | 버튼 | 출구 아래 1개씩. 색 = 음료 색. 고른 버튼에 테두리 | 누르면 1픽셀 눌림과 번쩍임 |
| 캔 | 떨어지는 캔 | 위에서 본 캔 윗면 (원, 테두리, 따개, 반사광). 은색 | 착지하면 그 출구의 음료 색으로 바뀜 |

### 2.3 상태별 화면

| 상태 | 화면 | 다음 상태로 가는 조건 |
|---|---|---|
| 준비 | 판과 버튼이 보이고, 캔이 투입구에서 달그락거린다. 버튼은 이때부터 누를 수 있다 | `startDelay`가 지난다 |
| 낙하 | 캔이 핀 사이를 작게 튀며 한 줄씩 내려간다. 줄마다 조금씩 빨라진다 | 캔이 출구에 들어간다 |
| 착지 | 캔이 3번 작게 튀며 멈추고, 음료 색으로 바뀐다. 버튼 입력과 닫기를 받지 않는다 | `landDuration`이 지난다 |
| 결과 | 메카닉이 `End(결과 이름)`을 부른다 | 0.6초 뒤 창이 닫힌다 (프레임워크 공통) |

## 3. 기능 명세

### 3.1 조작

| 입력 | 키보드 / 마우스 | 동작 |
|---|---|---|
| Navigate (좌우) | A, D, 왼쪽, 오른쪽 화살표 | 버튼을 고른다 |
| Submit | Space, Enter, E | 고른 버튼을 누른다 |
| Point + Click | 마우스를 버튼에 올리고 클릭 | 그 버튼을 고르고 누른다 |
| Alt | - | 쓰지 않는다 |

### 3.2 규칙
1. 캔은 한 번에 한 줄씩 내려간다.
2. 핀에서는 `pegRightChance` 확률로 오른쪽 아래, 나머지 확률로 왼쪽 아래로 간다.
3. 판 끝을 넘으려 하면 벽에 맞고 안쪽으로 튕겨 들어온다.
4. 게이트 줄은 레인 가운데에 있다. 그래서 캔은 반드시 게이트 하나에 닿는다.
5. 버튼 i를 누르면 게이트 i가 `gateOpenTime`초 동안 열린다. 다른 게이트가 열려 있으면 그 게이트는 닫힌다. 한 번에 1개만 열린다.
6. 캔이 닿는 순간 게이트가 열려 있으면, 캔은 그 출구로 바로 떨어진다.
7. 캔이 닿는 순간 게이트가 닫혀 있으면, 캔은 핀과 같이 무작위로 튄다. 그다음 마지막 줄 핀(칸막이 위)에서 양옆 출구 중 하나로 들어간다.
8. 캔이 출구에 들어가면 그 출구의 `outcome` 이름으로 끝난다.

### 3.3 진행 변수

| 변수 | 뜻 | 바뀌는 시점 |
|---|---|---|
| `outlet` | 캔이 들어간 출구 번호 (1부터) | 캔이 출구에 들어갈 때 |
| `presses` | 버튼을 누른 횟수 | 버튼을 누를 때 |
| `time` | 경과 시간 (초, 공통) | 매 프레임 |

### 3.4 메카닉이 직접 내는 결과

| 결과 이름 | 언제 |
|---|---|
| 출구의 `outcome` 값 | 착지 연출이 끝날 때. 미니게임 문서의 결과 판정 표에 같은 이름이 있어야 한다 |

### 3.5 예외 처리

| 상황 | 처리 |
|---|---|
| 준비, 낙하 중 닫기 | 프레임워크 공통 중단(`Aborted`). `abortActions`를 실행한다 |
| 착지 중 닫기 | 무시한다. 결과가 이미 정해졌으므로 보상을 잃지 않게 한다 (`CanAbort`가 false) |
| 스테이지가 너무 작아 판을 만들 수 없음 | 정의의 `MinStageResolution`이 출구 수에 맞는 최소 크기를 알려 준다. 프레임워크가 스테이지를 그 크기 이상으로 늘린다 |
| 출구 수가 2~8개가 아님, 정의 타입이 `GateDropDefinition`이 아님 | 정의 오류다. 오류 로그를 남기고 바로 중단(`Aborted`)한다 |

## 4. 연출 명세
"쫀득한" 손맛이 이 형식의 핵심이다. 아래 연출을 모두 넣는다.

| 순간 | 연출 |
|---|---|
| 준비 | 캔이 투입구에서 좌우로 흔들리고 따개가 달그락거린다 (기대감) |
| 핀 사이 이동 | 작은 포물선으로 튄다. 아래 줄로 갈수록 빨라지고 낮게 튄다. 그림자는 높이에 따라 작아지고 멀어진다. 그림자는 캔 지름부터 2픽셀씩 작은 홀수 지름 원이고, 캔 지름의 60%까지 작아진다 |
| 핀 충돌 | 캔이 납작해졌다 세로로 늘어난다 (미리 그린 타원 프레임. 가로 +2, 세로 -2 픽셀까지). 튄 방향으로 따개가 돈다. 핀이 밝아지고 1픽셀 밀렸다 돌아온다. 작은 불똥 몇 픽셀. 아래 줄일수록 낮은 핀 소리 |
| 벽 충돌 | 벽 쪽으로 튀었다가 벽에 맞고 안쪽 다음 핀으로 떨어진다. 불똥과 벽 소리 |
| 버튼 누름 | 버튼이 1픽셀 눌리고 번쩍인다. 버튼에서 게이트까지 같은 색 빛줄기가 올라간다. 고른 버튼 테두리는 스프링으로 미끄러진다 |
| 게이트 열림, 닫힘 | 문짝이 바깥 경첩을 축으로 아래로 열린다. 스프링이라 지나쳤다가 돌아온다 |
| 닫힌 게이트 충돌 | 문짝이 눌렸다 튀어 오르고 번쩍인다. 스테이지가 1픽셀 흔들린다 |
| 열린 게이트 통과 | 문짝이 한 번 더 밀려 흔들리고, 캔이 출구로 곧장 떨어진다 |
| 착지 | 3번 작게 튀며 멈춘다. 출구가 빛나고, 캔 윗면이 가운데부터 음료 색으로 차오른다 (4단계. 마지막에 테두리까지 한 번 부풀었다가 돌아온다). 같은 색 색종이와 올라가는 아르페지오. 꽝(`dud`)은 색종이 대신 출구 색 연기와 김빠진 소리. 스테이지가 1픽셀 흔들린다 |
| 공통 | 그림 위치는 스테이지 픽셀 격자에 맞춰 픽셀 그림이 흐려지지 않게 한다. 캔의 눌림, 그림자 크기, 음료 색 차오름은 스프라이트 배율을 바꾸지 않고 미리 그린 프레임을 바꾼다 |
| 소리 | 지금은 코드로 만든 임시 소리다 (`GateDropSound`). 정식 소리가 생기면 `Audio/SFX/`의 클립으로 바꾼다 |

## 5. 파라미터 명세
`GateDropDefinition`에 들어가는 값이다.

| 파라미터 | 타입 | 기본값 | 범위 | 설명 |
|---|---|---|---|---|
| `outlets` | 출구 목록 | - | 2~8개 | 출구마다 `outcome`(결과 이름), `color`, `label`(창 상태 줄에 보일 이름, `@키` 가능), `dud`(꽝 연출). 버튼과 게이트도 이 수만큼 생긴다 |
| `pegRightChance` | float | 0.5 | 0~1 | 핀과 닫힌 게이트에서 오른쪽으로 갈 확률 |
| `startDelay` | float | 0.6 | 0 이상 | 준비 상태 시간 (초) |
| `gateOpenTime` | float | 0.45 | 0 초과 | 버튼을 누른 뒤 게이트가 열려 있는 시간 (초) |
| `firstHopDuration` | float | 0.3 | 0 초과 | 첫 줄에서 한 줄 내려가는 시간 (초) |
| `lastHopDuration` | float | 0.15 | 0 초과 | 마지막 줄에서 한 줄 내려가는 시간 (초). 그 사이 줄은 선형 보간한다 |
| `hopHeight` | float | 3.5 | 0 이상 | 핀에 맞고 튀는 높이 (스테이지 픽셀). 맨 아래 줄에서 55%까지 줄어든다 |
| `landDuration` | float | 0.8 | 0 초과 | 출구에 들어간 뒤 결과를 내기까지의 시간 (초) |
| `boardColor` | Color | (0.16, 0.29, 0.31) | - | 판 배경색. 테두리, 홈, 얼룩 색은 이 색에서 만든다 |
| `canColor` | Color | (0.78, 0.8, 0.83) | - | 떨어지는 캔 윗면 색 (착지 전) |

판 배치는 스테이지 크기에서 계산한다 (`GateDropLayout`, 상수는 `GateDropDefines`).
- 레인 폭은 짝수이고 10~24 픽셀이다. 캔 지름은 홀수이고 7~15 픽셀이다.
- 핀 줄 간격의 목표는 레인 폭 x 0.72다. 줄 수와 레인 수의 합은 홀수다. 그래야 게이트 줄이 레인 가운데에 온다.
- 핀 줄 간격의 최소는 레인 폭 x 0.5(반 레인)다. 캔이 튈 때 45도보다 눕지 않게 하기 위해서다. 최소보다 좁아지는 줄 수는 고르지 않는다.
- 가장 적은 줄 수로도 최소 간격이 나오지 않으면 레인 폭을 2픽셀씩 줄인다. 넓고 낮은 스테이지에서 생긴다. 예: 160x96, 출구 6개이면 레인 폭 18, 줄 3개다.
- Plaza 자판기(104x176, 출구 6개)는 레인 폭 16, 캔 지름 11, 줄 11개다.
- 게이트 줄은 마지막 줄(칸막이 위 핀)보다 캔 지름 + 3 픽셀 위에 있다 (`GateRowGap`). 마지막 줄 핀 위의 캔이 문짝과 겹치지 않게 하기 위해서다.

## 6. 구현 명세

코드는 모두 `Scripts/Content/Minigame/GateDrop/`에 있다.

| 항목 | 이름 |
|---|---|
| 메카닉 클래스 | `GateDropMinigame` (`MinigameBase<GateDropDefinition>`). 단계 진행, 입력, 결과 |
| 정의 클래스 | `GateDropDefinition`. 생성 메뉴는 `LOTW/Minigame/Gate Drop Definition` |
| 판 규칙 | `GateDropBoard` (순수 C#. 줄과 열, 핀 위치, 벽 반사. EditMode 테스트 대상) |
| 판 배치 | `GateDropLayout` (스테이지 크기 -> 픽셀 위치, 포인터 위치 -> 레인. EditMode 테스트 대상) |
| 이동 곡선 | `GateDropHop` (포물선 한 번) |
| 화면 조립 | `GateDropView` (스프라이트 생성, 흔들기, 커서, 빛줄기) |
| 부품 연출 | `GateDropCan`, `GateDropPeg`, `GateDropGate`, `GateDropButton`, `GateDropPocket`, `GateDropParticles`, `SpringValue` |
| 임시 그림, 소리 | `GateDropArt` + `PixelCanvas` (실행 중에 그림을 그린다), `GateDropSound` (실행 중에 소리를 만든다) |
| 스테이지 프리팹 | `Prefabs/Minigames/PF_Minigame_GateDrop` (메카닉과 직교 카메라만 있다. 판은 `OnBind`에서 만든다) |
| 정식 그림 | 아직 없다. 생기면 `Art/Minigames/GateDrop/`에 둔다 |

- 물리 엔진을 쓰지 않는다. 캔은 칸 단위로 움직이고 칸 사이는 연출로만 그린다. 그래서 결과가 재현되고 테스트할 수 있다.
